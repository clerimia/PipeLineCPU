# 控制信号设计

## 控制信号总览

五级流水线CPU的控制信号分为以下几类：
1. **指令控制信号**：由控制单元根据操作码生成
2. **流水线控制信号**：由冲突检测单元生成
3. **前推控制信号**：由前推单元生成

---

## 1. 指令控制信号

### 控制信号列表

| 信号名 | 位宽 | 功能描述 |
|--------|------|----------|
| RegWre | 1 | 寄存器写使能，1=写入，0=不写 |
| RegDst[1:0] | 2 | 写寄存器地址选择：00=$31, 01=rt, 10=rd |
| ALUSrcA | 1 | ALU输入A选择：0=ReadData1, 1=sa（移位量） |
| ALUSrcB | 1 | ALU输入B选择：0=ReadData2, 1=extend（立即数） |
| ALUOp[2:0] | 3 | ALU操作选择 |
| mRD | 1 | 数据存储器读使能，1=读 |
| mWR | 1 | 数据存储器写使能，1=写 |
| DBDataSrc | 1 | 写回数据源：0=ALU结果, 1=存储器数据 |
| WrRegDSrc | 1 | 写寄存器数据源：0=PC+4, 1=数据总线 |
| ExtSel | 1 | 立即数扩展方式：0=零扩展, 1=符号扩展 |

## 3. 流水线控制信号

### 由冲突检测单元（HazardDetectionUnit）生成

| 信号名 | 位宽 | 功能描述 |
|--------|------|----------|
| PC_Write | 1 | PC写使能：1=正常更新，0=暂停 |
| IF_ID_Write | 1 | IF/ID寄存器写使能：1=正常传递，0=保持 |
| IF_Flush | 1 | IF阶段清空：1=插入NOP，0=正常 |
| ID_EX_Flush | 1 | ID/EX阶段清空：1=插入气泡，0=正常 |

### 控制信号生成条件

#### Load-Use冒险检测
```
条件：EX阶段为Load指令 AND Load目标寄存器是ID阶段源寄存器
动作：
  - PC_Write = 0       (暂停PC)
  - IF_ID_Write = 0    (暂停IF/ID)
  - ID_EX_Flush = 1    (插入气泡)
```

#### 控制冒险检测
```
跳转指令 (J, JAL, JR)：
  - IF_Flush = 1       (清空IF阶段已取指令)

分支指令 (BEQ, BNE, BLTZ) - 关键修复：
  - 在ID阶段判断分支条件
  - 支持MEM阶段数据前推到分支比较
  - 只有实际跳转且未暂停时才清空：
    IF_Flush = is_branch && (PCSrc != 00) && PC_Write
  - 避免暂停时错误清空分支指令本身

HALT指令：
  - PC_Write = 0       (停止PC更新)
  - IF_ID_Write = 0    (停止流水线)
```

#### 分支指令数据冒险处理（重要）
```
1. EX阶段冒险 - 需要暂停：
   条件：EX阶段指令将写入分支指令需要的寄存器
   动作：
     - PC_Write = 0
     - IF_ID_Write = 0
     - ID_EX_Flush = 1
   原因：EX阶段数据还未准备好，无法前推

2. MEM阶段冒险 - 通过前推解决，不暂停：
   条件：MEM阶段指令将写入分支指令需要的寄存器
   动作：在PCSrc生成逻辑中直接前推EX_MEM_ALU_result
   原因：MEM阶段数据已准备好，可直接使用
   注意：这是关键修复，旧版本会导致无限暂停

3. WB阶段冒险 - 寄存器堆内部前推：
   条件：WB阶段写入与ID阶段读取同一寄存器
   动作：寄存器堆内部前推，直接读到最新值
   原因：同周期写后读支持
```

## 4. 前推控制信号

### 由前推单元（ForwardingUnit）生成

| 信号名 | 位宽 | 功能描述 |
|--------|------|----------|
| ForwardA[1:0] | 2 | ALU输入A前推控制 |
| ForwardB[1:0] | 2 | ALU输入B前推控制 |

### 前推控制编码

| ForwardA/B | 数据源 | 说明 |
|------------|--------|------|
| 00 | 寄存器堆 | 不前推，使用正常的寄存器读取值 |
| 01 | WB阶段 | 从MEM/WB流水线寄存器前推 |
| 10 | MEM阶段 | 从EX/MEM流水线寄存器前推 |
| 11 | 保留 | 未使用 |

### 前推条件

#### EX冒险（从MEM阶段前推）
```verilog
if (EX_MEM_RegWre && 
    (EX_MEM_WriteReg != 0) && 
    (EX_MEM_WriteReg == ID_EX_rs))
    ForwardA = 2'b10;

if (EX_MEM_RegWre && 
    (EX_MEM_WriteReg != 0) && 
    (EX_MEM_WriteReg == ID_EX_rt))
    ForwardB = 2'b10;
```

#### MEM冒险（从WB阶段前推）
```verilog
else if (MEM_WB_RegWre && 
         (MEM_WB_WriteReg != 0) && 
         (MEM_WB_WriteReg == ID_EX_rs))
    ForwardA = 2'b01;

else if (MEM_WB_RegWre && 
         (MEM_WB_WriteReg != 0) && 
         (MEM_WB_WriteReg == ID_EX_rt))
    ForwardB = 2'b01;
```

## 5. PC更新控制

### PC来源选择（PCSrc[1:0]）

| PCSrc | PC来源 | 说明 |
|-------|--------|------|
| 00 | PC + 4 | 顺序执行 |
| 01 | PC + 4 + offset*4 | 分支跳转（BEQ, BNE, BLTZ） |
| 10 | $rs | 寄存器跳转（JR） |
| 11 | {PC[31:28], addr, 2'b00} | 直接跳转（J, JAL） |

### PC更新条件
```verilog
PC更新 = PCWre AND PC_Write

其中：
- PCWre：指令不是HALT时为1
- PC_Write：无冒险或无需暂停时为1
```

## 6. 控制信号时序关系

### 流水线各阶段的控制信号

```
阶段      生成的控制信号                    使用的控制信号
─────────────────────────────────────────────────────────
IF      无                               PC_Write, IF_Flush
        
ID      RegWre, RegDst, ALUSrcA,        IF_ID_Write
        ALUSrcB, ALUOp, mRD, mWR,
        DBDataSrc, WrRegDSrc, ExtSel
        
EX      ForwardA, ForwardB              ID_EX的所有控制信号
        
MEM     无                               EX_MEM的所有控制信号
        
WB      无                               MEM_WB的所有控制信号
```

### 控制信号传递路径

```
控制单元(ID) → ID/EX寄存器 → EX阶段
                ↓
            EX/MEM寄存器 → MEM阶段
                ↓
            MEM/WB寄存器 → WB阶段
```

## 7. 冒险检测优先级

当多个冒险同时发生时，按以下优先级处理：

1. **Load-Use冒险**（最高优先级）
   - 必须暂停流水线
   - 无法通过前推解决

2. **EX冒险**
   - 通过从MEM阶段前推解决
   - 优先于WB前推

3. **MEM冒险**
   - 通过从WB阶段前推解决

4. **控制冒险**
   - 通过清空流水线解决
   - 造成1-2个周期的延迟

---

## 8. 控制信号优化

### 减少冒险的方法

1. **编译器优化**：重排指令，避免紧邻的数据依赖
2. **分支延迟槽**：在分支指令后添加一条总会执行的指令
3. **分支预测**：预测分支方向，减少错误预测的损失
4. **多发射**：增加执行单元，同时执行多条指令

### 当前实现的优化

- ✅ 数据前推机制
- ✅ 内部前推（寄存器堆同周期写后读）
- ✅ Load-Use冒险检测与暂停
- ✅ 控制冒险的流水线清空

### 未来改进方向

- ⏸️ 分支预测
- ⏸️ 分支延迟槽
- ⏸️ 更复杂的前推路径
